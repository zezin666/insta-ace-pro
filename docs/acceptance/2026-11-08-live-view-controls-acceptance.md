## 结果

### 通过

1. **实时预览**：进入「实时画面」后成功建立 TCP 连接并解码播放，状态显示「预览中」。
2. **预览比例**：预览框按实际推流比例显示为约 4:3（不是固定 16:9，也未拉伸）；高度受可用空间限制时居中留黑边。
3. **状态区**：右上角显示模式 chip；本次相机查询返回不可用状态，显示「未知」。
4. **错误可见且可重试**：点「拍照」或「录制」后显示「无法切换相机模式（相机返回 400）」，不发送拍照/录像命令；连接保持 `Connected`，实时预览继续播放，再次点击会重试。
5. **互斥/防抖**：快速连续点击「拍照」「录制」只发生一次动作，无崩溃、无交叉命令。
6. **横屏**：不锁定方向；预览仍在控制区上方，按比例缩小并留黑边，两个按钮均可见（符合设计 §4.4「高度不足时预览按比例缩小并留黑边」）。横屏可用高度较小，预览偏小。
7. **回归**：相册列表、缩略图、下载、查看器、设置页在安装后未发现异常。

### 未通过 / 已知限制（阻塞核心目标）

**命令 54 `SET_SYNC_CAPTURE_MODE` 与命令 55 `GET_SYNC_CAPTURE_MODE` 被该相机固件拒绝（响应码 400）。**

证据（手机端原始 TCP 探测，`/data/local/tmp/probe.sh`，与 App 使用相同的帧格式）：

| 请求 | 载荷 | 响应码 |
|---|---|---|
| 命令 13 `GET_FILE_LIST`（对照） | `08 02 10 00 18 64` | 200，返回文件列表 |
| 命令 55（空载荷） | — | 400 |
| 命令 55（`08 00`） | 字段 1 = 0 | 400 |
| 命令 54（`08 01`） | `NORMAL_IMAGE` | 400 |

- 探测发生在**没有实时推流**的新连接上，因此不是「推流中不允许切换」的时序问题。
- 帧头、SYNC/keepalive、长度字段均与能正常工作的命令 13 一致，排除了封包格式问题。
- 结论：本固件不接受计划所假设的 54/55 命令编号或消息体。需要从对应固件的官方 App/SDK（`libOne.so` 中的 protobuf 描述符）重新确认命令定义后才能实现真正的模式切换。

因此以下验收项无法完成：

1. 相机在视频模式时点「拍照」自动切照片并拍照成功、模式保持。
2. 相机在照片模式时点「录制」自动切视频、开始/停止录制、模式保持。
3. 8211 `SYNC_CAPTURE_MODE_UPDATE` / 8234 `UPDATE_LIVE_STREAM_PARAMS` 通知未观察到（模式切换未成功，无法触发）。
4. 模式切换后推流中断 → 自动重启的端到端验证（无法触发切换）。
